# R22：发布页交互与异步反馈

日期：2026-11-10，Asia/Shanghai。用户批准 [R21 交互清单](review-ux-r21.md) 后实施。沿用冻结 SaaS 导航和当前整库发布规则，以下为本地 Web/BFF 交互改进，没有新增 SaaS 观察、接口猜测、业务功能或 Oxen 内核修改。

## 已实现清单

| ID | 实施内容 | 保留边界 |
|---|---|---|
| UX01 | 列表读取错误、操作错误、分享读取错误分开；后台打包轮询不清除操作失败提示。操作提示仅在显式新操作、关闭提示或上下文切换时清除 | 不把后续 GET 成功当作前一次写入成功 |
| UX02 | 请求捕获项目、列表类型、身份 ID、凭据 ID及所选版本；旧上下文的读回、错误和一次性分享地址不能写入新页面。已确认写返回会使更早启动的 GET 失效 | 不读取原始令牌作为上下文，不把权限判断交给前端 |
| UX03 | 候选、快照、发布和勘误的成功写返回立即保留；随后 GET 失败显示“操作已完成，但列表刷新失败”，提供只读重试。分享创建后即保留仅显示一次的链接，不因读回失败丢失 | 重试刷新不再次 POST；不能仅因读取失败宣称写入失败 |
| UX06 | 快照使用“全部状态／可下载快照／待完成或失败”；进入其他子页重置不适用状态条件，保留搜索。发布专属条件不再把 ready 快照筛空 | 不增加新状态或新快照能力 |
| UX07 | Tab 建议检查输入法组合状态和修饰键，只在普通 Tab、非组合、空值情况下采纳 | 不阻止正常焦点移动，不覆盖作者已输入内容 |
| UX08 | 有数据但被筛选为空时显示“没有匹配的版本”和“清除筛选”；真实空项目才显示“创建第一个 Release”。读取失败单独提供重试，不伪装成首次空库 | 不删除任何版本或隐式修改筛选数据 |
| UX09 | 表单主动作“保存并校验”顺序执行一次保存及一次打包；次要动作“仅保存候选”继续独立可用。保存返回 ID 与修订立即保留，打包失败继续显示同一候选 | 不重复创建候选；最终“核对并发布”和替换确认仍独立执行 |
| UX10 | 重复范围规则集中到“发布与导出规则”展开区；数据提交、数量、比较基线和主动作靠前；表单说明区域更紧凑、页头／操作栏保持可达 | 校验问题、后端警告、待清理提示及最终替换风险不折叠或取消 |

删除结果核对接入 UX04 提供的统一 `removeAndVerify`、`verifyDeletion` 与 `isUnknownOperationError`：未知结果只读取状态，不重发 DELETE。只读核对只能说明链接当前已撤销或不存在，不伪称一定由本次请求执行。其他未知写入保留输入并锁重复提交，必要时从新窗口打开已有“操作核对”，不新建虚假核对接口。

## 代码映射

- `components/ReleasesPanel.vue`：分离反馈、上下文捕获、成功对象保留、串行主动作、快照条件和紧凑信息层级。
- `release-requests.ts`：实际用于页面的上下文票据、异步读取、确认结果合并、候选保存／校验串行流程和空状态判断。
- `release-form-hints.ts`：组合输入与修饰键保护。
- `components/releases.css`：新样式使用共享颜色与间距／文字／阅读宽度 tokens；没有修改部署产物。
- `r22-release-requests.test.ts`：可控 Promise 故障和迟到响应测试，不依赖浏览器内部状态或测试专用页面分支。

## 自动验证

`npx vue-tsc --noEmit -p apps/web/tsconfig.json` 通过。`r22-release-requests.test.ts` 与既有 `r21-release-ui.test.ts` 合计 **16/16 通过**，覆盖：

1. 读失败后保留上次真实结果，后续后台读取不清操作 409。
2. 项目、身份、凭据和所选版本变化后丢弃迟到分享结果及错误。
3. POST 成功后 GET 失败保留返回 ID，GET 重试不增加写入次数。
4. 写入确认前启动的旧 GET 不覆盖新确认对象。
5. 保存与打包顺序、双击只保存一次、使用保存返回的精确修订。
6. 打包失败保留同一候选，重试不创建第二份候选；上下文变化后不额外发起打包。
7. 新发布合并不丢候选，更早的 queued 返回不覆盖更晚的 ready 状态。
8. 筛选空状态、首次空状态、IME Tab、明确分享授权及 R21 清理提示。
9. 项目 A 的写入尚未返回时，项目 B 可独立保存；返回仍有待处理写入的同一上下文时保留去重，并明确提示处理中，不静默吞掉点击。

这些是前端异步逻辑及既有发布语义检查，不冒充浏览器或真实网络故障已实测。

远端浏览器回归新增七项 R22 场景，保留原五项，共十二项已在 [Actions 42831759415](https://github.com/bigsinger/OxenWeb/actions/runs/42831759415) 实际通过。普通 Tab 与 `isComposing` 护栏既有单元验证，也通过远端真实DOM `KeyboardEvent`组合状态检查；这不等于手动操作并验证 Windows 原生输入法候选窗。

## 浏览器验收交接

由主任务使用隔离合成项目实际核对：

| 场景 | 可见结果 |
|---|---|
| 后台打包时操作被 409 拒绝 | 两次以上轮询后原因仍可读，列表仍更新 |
| 延迟分享 GET 后切换版本／身份 | 新页面没有旧分享地址、列表或错误 |
| 保存成功，列表 GET 故障 | 原 ID 和详情保留；只读重试后无第二份候选 |
| “保存并校验”成功／打包失败／快速双击 | 一次候选保存；失败时保留同一候选，发布仍需最终确认 |
| 仅保存候选 | 保留草稿，未自动打包或发布 |
| 切换快照与发布筛选、输入不存在版本 | 条件适用、空状态和清除入口准确 |
| 中文输入、390px、较长自动说明 | Tab 不干扰组合输入；主要统计、操作和风险信息可访问 |
| 删除响应丢失或核对失败 | 不重发删除；状态未知时保留上下文，只读核对 |

上述表是最初交接清单，最终结果以 [R22主记录](implementation-r22.md) 为准。合成CUA已实际覆盖写后GET503、只读恢复、独立快照筛选、被筛空与首次空状态、普通Tab、人工标题保留、390px主次按钮及最终发布取消。严格迟到响应、轮询错误保持、保存去重及输入法组合事件另由远端浏览器／deferred逻辑测试覆盖；不把手工近似切换视为严格并发证明。本子任务未改写真实样本。
