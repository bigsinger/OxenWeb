# AI 安全标注预设与版本化标签设计

更新：2026-11-08。本文记录本地实现，不是 Oxen SaaS 原生接口说明。

本项目在 `.oxenweb/labels.json` 中保存标签规范、数据集／文件／条目赋值和模板来源，每次保存形成 Oxen 版本提交。模板只创建可编辑的标签列，不读取记录正文推断结论，不生成默认人工判定，不运行样本、技能或评测。

分类设计参考 [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/llm-top-10/) 中的提示词注入、敏感信息暴露和供应链等风险方向；2026-11-08 已核对官方目录。下述字段、选项、语义键、流程与“行为偏离”细分均由本项目自行定义，不是 OWASP 官方标注规范、认证标准或完整映射。实现权威来源为 `apps/server/src/label-templates.ts`，本地契约为 `packages/shared/src/index.ts`。

## 判定原则

- **基准真值**保留在原始记录或独立清单中。`ai.ground_truth_reference` 只记录字段／清单位置及解释，不覆盖源字段，也不自动复制它的值。
- **人工安全判定**是独立的人工作业结论：良性、恶意、不确定、不适用。积极或消极措辞都不能直接推断恶意；存在敏感数据也不等于存在恶意意图。敏感数据是否存在、属于哪一类，由 `sensitive.categories` 单独记录。
- **预期行为**说明在任务与授权下应如何响应；**观察行为**说明实际测试发生了什么。攻击请求存在不表示攻击成功，执行错误不表示安全，模板也不会运行测试。
- **待审核**是工作流尚未开始；**未知**是当前信息不足；**不确定**是已经审核但不能作出安全判定；**不适用**是维度本身不适用。空值表示没有赋值，不会被自动解释成上述任何状态。
- **严重度**评估影响，**置信度**记录审核者对证据的确信程度。它们不是同一指标，置信度也不是模型概率。
- 对多选列，具体类别与“未发现／未知／不适用”应按标注规范合理选用。当前校验保证选项存在且不重复，不推断这些值的业务互斥关系。

## 模板复制、自定义与冲突规则

`LabelDocument.version=1`、`LabelTemplate.version=1`、导出容器 `version=1` 是三个独立的版本号。模板应用将当前选中定义复制到仓库版本文件；此后修改目录不会自动更改已经应用的列。

本次版本交付前，版本 1 目录的最终默认层级已包含条目级的数据来源、任务类型、技能来源／审核建议和行为偏离基线目标／版本。此前在本次未发布联调中复制到四个基准仓库的配置，另以一次显式 CAS 批量提交补充这些列的 R 层级；该操作只扩展适用范围，保留列名、选项、赋值与原模板来源。它不是后台自动同步模板目录，用户后续定制仍独立保存。

列的 `id` 是赋值引用；`semanticKey` 是跨模板去重身份。匹配语义键时复用现有列，完整保留用户修改后的列名、类型、选项、说明和层级。没有语义键的旧自定义列不会因同名而被擅自认定等价：遇到 ID 或名称冲突返回 409，用户可以重命名旧列或取消选择冲突列。已绑定的语义键不能直接改为另一个语义键；可另建自定义列。

一次应用选中的全部列和来源记录使用同一个专用 workspace、同一次 CAS 提交。`expectedCommit` 必须等于分支头；分支移动时不覆盖新版本。所有原有列、赋值与迁移记录保留。相同模板版本的相同键已应用且列仍存在时，重复操作返回当前状态，不产生重复提交。新模板即使只复用已有列，也会记录来源；新增选择会追加来源记录。

`templateApplications` 每条记录包含 `templateId`、`templateVersion`、`appliedAt`、`sourceCommitId`、`selectedKeys` 和语义键到列 ID 的 `columnIds`。它记录应用时的来源，不是用户后来修改列的完整差异；后续修改由 Oxen 提交历史追踪。删除列会删除对应赋值，既有来源记录保留在历史中。

三级赋值相互独立，不自动向下继承或汇总：D 记录整个仓库数据集，F 使用仓库相对 `path`，R 使用 `path + rowId`。同一对象最多一条赋值记录，`values` 按列 ID 保存。服务端检查层级、列、选项和基数；新文件／条目赋值还检查目标存在及稳定行 ID。列没有 `scopes` 时兼容原有三级标签。修改类型、选项或层级若使已有赋值无效，会明确拒绝，需先整理现有值。

## 本地 BFF API

以下均为本地扩展，不是手写猜测的 Oxen 上游接口。仓库前缀为 `/api/repos/:namespace/:repo`。读取遵循现有身份和仓库读取权限；保存需要仓库写入权限，浏览器会话写入还需现有 CSRF 保护。

| 方法与路径 | 输入／输出 | 行为 |
| --- | --- | --- |
| `GET /api/label-templates` | 返回 `LabelTemplate[]` | 取得版本 1 的目录、说明、适用层级、选项说明和参考链接 |
| `GET {repo}/labels?ref=...` | 返回 `LabelState` | 将分支或提交解析为固定版本，返回标签与版本上下文 |
| `POST {repo}/labels/templates/apply` | 见下例；返回 `LabelState` | 一次 CAS 提交复制模板列和来源记录 |
| `POST {repo}/labels/columns` | `{ref,expectedCommit,column,message?}` | 新建或按 ID 更新自定义列 |
| `DELETE {repo}/labels/columns/:columnId` | `{ref,expectedCommit,message?}` | 删除列及对应赋值 |
| `POST {repo}/labels/assignments` | `{ref,expectedCommit,scope,path?,rowId?,values,message?}` | 替换当前对象的赋值；空对象清除赋值 |
| `PUT {repo}/labels` | `{ref,expectedCommit,columns,assignments,message?}` | 整体保存规范与赋值，保留既有模板来源与旧标注迁移信息 |
| `POST {repo}/labels/migrate` | `{ref,expectedCommit,message?}` | 显式迁移旧标注；未匹配项目保留供人工处理 |
| `GET {repo}/labels/export?ref=...` | 下载 JSON 附件 | 导出固定版本的标签快照，不生成提交 |

应用请求示例（仅展示结构，不含真实样本）：

```json
{
  "ref": "main",
  "expectedCommit": "<current-commit-id>",
  "templateId": "prompt-injection",
  "templateVersion": 1,
  "selectedKeys": ["general.review_status", "ai.human_judgment", "ai.evidence"]
}
```

省略 `selectedKeys` 应用全部列；空列表、重复键或未知键返回 422。未知模板返回 404，模板版本不符或列冲突返回 409。历史提交不可直接写入，须选择分支。应用接口严格校验字段，不接受 `message`；提交说明由模板名称和版本生成。未提交的表单草稿不会包含在模板应用或快照导出中。

## 标签快照导出与稳定 ID 关联

导出响应为 `application/json` 附件，文件名只含受控字符并限制长度。响应使用 `Cache-Control: no-store`，继承仓库读取 ACL；导出不创建 workspace 或提交。界面使用当前已加载的 `state.commitId` 导出，避免分支随后移动改变用户看到的版本。

```text
format: "oxen-web-label-snapshot"
version: 1
namespace / repo: 仓库身份
ref: 本次请求的分支或提交
fixedCommitId: 此次解析后固定读取的提交
exportedAt: 导出时间（UTC ISO 8601）
storagePath: ".oxenweb/labels.json"
document:
  version: 1
  columns: 完整列定义、说明、选项、层级及语义键
  assignments: 完整三级赋值
  templateApplications?: 模板来源记录
  legacyMigration?: 已版本化的迁移信息与未匹配记录
legacy:
  unmigratedCount: 此固定版本可见但尚未迁移的旧标注数
```

关联应以仓库身份和 `fixedCommitId` 为版本上下文：数据集赋值按 `scope=dataset`；文件赋值按 `scope=file + path`；条目赋值按 `scope=row + path + rowId`。`values` 的键对应 `document.columns[].id`，跨模板身份可进一步看 `semanticKey`。不要把 `rowId` 当作显示行号或任意源字段 `id`。

JSONL 解析时，若所有记录都有唯一字符串／数字 `id`，稳定行标识由带类型的业务 ID 派生；否则使用规范化记录摘要和重复项序号。其他表格格式也可能使用 Oxen 行 ID。应使用同一固定版本文件预览返回的 `rowIds` 关联；不能将旧标签按当前位置套用到已变更文件。正常结构化编辑会同时维护支持的条目映射。

该附件是**标签快照**：不合并源 JSONL／CSV 内容，不携带浏览器未保存草稿，不输出训练样本或评测报告，也不自动把未迁移的旁路旧标注变成有效赋值。需要源数据时，应另取相同 `fixedCommitId` 的文件，再按稳定标识关联。未匹配的迁移记录应人工处理，不能按猜测的行号回填。

## 技能样本与范围

技能安全标注采用“一份技能 ZIP 对应一条清单记录”的数据表示；一条记录可包含清单、文本摘要、来源和归档引用，用条目级标签记录该技能的人工判断。ZIP 内多个文件不自动成为多个独立样本，风险证据应标明归档内相对路径与位置。文件级和数据集级字段记录共享的规范、来源或基线，避免让每条样本重复填写。

本地准备工具为 `scripts/benchmark-bundles.py`。它的 `--stage` 操作将外层归档中每个 `packages/skill-NNNNNN/` 目录打包为独立 ZIP，规范清单为 `data/samples.jsonl`，每条记录包含稳定 `id`、`package_path`、`package_sha256`、`package_bytes`、`file_count`、`uncompressed_bytes`、原样保留的 `ground_truth` 对象及 `__bundle_provenance`。内部嵌套 ZIP 保持不透明，不递归展开；原始归档在 `source/archives` 保留。具体参数与完整性检查以该工具为准。模板中的“基准真值引用”可记录 `ground_truth` 的位置，人工判定继续独立保存。

技能内容作为不可信数据阅读，导入或标注不意味着安装、执行或授权访问网络；文本抽取受支持格式和本地资源限制约束，未提取内容不能视为已经审核。归档引用与摘要不能替代必要的人工源码检查。准备与导入工具的输入限制以对应工具文档为准。

本次功能覆盖结构化数据、文本以及技能归档的清单式标注。图像、音频、视频的样本管理与专用标注、模型评测执行和云训练部署不在该标注模板设计范围。
