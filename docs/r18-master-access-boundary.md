# R18 主库与发布包的权限边界

用户已明确算法／QA只下载发布包，不进主库。当前实现仍不是样本级ACL：如果让某个人读取完整JSONL、ZIP原件、原始归档或历史，就无法仅靠表格中的hidden字段对其隐藏同一内容。

因此采用整个主库边界：已经采用任意全局字段的项目，以及历史上启用过受限模式的项目，其源数据仅向管理员或获授 `release.hidden` 的指定可信人员开放。该权限意味着可以读取整个主库及旧历史，授权界面应明确说明，不能把它当作只允许下载一个包。

`restricted-master-access.ts`通过统一请求守卫保护项目元数据、表格、查询／检索、raw／file／tree、源归档、提交／diff／恢复、工作区以及未来新增的项目路径。固定旧commit和切换分支不能绕过；权限撤销或控制面不确定时拒绝。项目目录在读取样本计数／标签前排除无源权限项目；项目job、个人操作对账入口也检查当前源权限。只有Releases／snapshots路径交由发布服务按资产继续鉴权，公开下载链接仅能获得已经授权的非隐藏资产。

没有主库权限的人员通过负责人发出的非隐藏发布包／受限分享链接使用数据，不登录项目表格。为日常标注授予主库权限意味着该标注人员也被信任读取隐藏数据；若要让其只标非隐藏行，需另设非隐藏私有项目，当前不宣称已支持贯穿历史的行级ACL。

旧提示词别名 `local/prompt-injection-bench` 与当前提示词主库有2000条重复，不能作为另一个可共享数据源。R18只读检查时其为private、协作者0，未修改其源与权限；未来也不可向算法／QA开放别名或原始归档。自动语义同源识别不等于自动跨项目ACL，负责人仍需维护所有副本的相同边界。

本机Oxen仅回环监听；拥有服务器操作系统／存储权限的人员不在Web角色的隔离边界内。此处未改Oxen服务端或内核，也不以Web筛选冒充底层文件隔离。

回归包含真实Fastify完整应用的主库目录／旧历史／raw／query拒绝，以及统一守卫的多个路径、显式指定读取、管理员、撤销和不确定状态。发布资产级过滤、快照裁剪及浏览器结果另见R18整体验收。
