# R20：完整数据集发布与自动 Release Notes

日期：2026-11-10，Asia/Shanghai。按负责人最新定位，发布只管理完整数据集版本，样本业务管理交给外部ES。全局“发布模板”、项目“视图管理”及相应配置／筛选／物化逻辑已移除。Oxen官方服务、内核和固定OpenAPI不变。

## 当前交互

|操作|行为|
|---|---|
|创建Release|填写版本、来源分支／提交和标题，自动读取固定提交并对比上一正式整库版本，生成可编辑的版本说明|
|变更说明|样本新增／修改／删除、人工标注、附件、字段／标签定义、README及文件增改删、提交摘要；在本机确定性计算，不向模型发送正文|
|比较基线|取本项目最近发布、未撤回、非预发布的`dataset-v1`正式版本；无可比版本时为首次完整发布。旧分层包不作为完整数据集基线，避免把旧主库提交误当作旧交付成员|
|保存候选|固定commit、比较基线及预览摘要CAS，变化返回409并保留输入；手工修改说明不会被重新检查覆盖，可显式重新采用自动说明|
|打包与发布|保存→校验并打包→核对发布，生成一个ZIP及一个manifest资产，发布后字节和说明固定；仍可指定最新稳定版、撤回、勘误及管理下载链接|
|工作快照|完整已提交数据的内部工作包，无视图选择器；仅创建者及授权身份可访问，不含私有未提交草稿，不生成公开外链|

每个正式包包含全部canonical条目，包含原README、样本、字段定义、数据集／文件／样本标签、可验证的关联附件、RELEASE_NOTES.md、manifest及checksums。保留字段“是否导出”投影和实际复核状态。split、quality、purpose／purposes、visibility等只是业务数据，不筛除行、不决定发布分层。Skill包继续作为压缩数据保存，不展开执行。Oxen控制文件、访问策略和令牌不进入包。

自动说明作为计算证据单独保留；用户编辑后的说明是最终RELEASE_NOTES内容，不重复拼接两份。候选创建时基线冻结，其他版本随后发布不会悄悄改写该候选；界面持续显示准确比较基线。提交摘要最多显示50条，遍历有界；祖先链不完整时明确提示，不伪造“无变化”。
