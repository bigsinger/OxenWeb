## 为什么要分开保留输入与提交

合法样本草稿、字段规范提交与用户正在输入的文本具有不同约束。未闭合 JSON、半个数字和尚未加入选项的表单不能提交为有效数据，却仍应在离开、刷新或处理另一项工作时保留。用真实字段 PUT 或草稿提交作为导航前提，会让任务/权限/校验拦截变成输入丢失。

因此增加独立的 BFF 本机检查点，按 actor/repo/branch/kind隔离；它保存控件原始状态，不产生版本、不解释或执行样本内容。导航等待保留结果，失败停留并重试。正式保存仍执行原有规则。恢复先读取最新版本：字段规范未变可承接最新样本提交；定义发生变化则先对照，不能从旧表单悄悄全量覆盖新规范。检查点更新和清理使用 ID+revision，冲突保留双方输入或由用户明确选择。

等待持久化并非只等待第一次请求：请求过程中还可能继续输入。离开前循环核对上下文与原始输入指纹，直到最新输入确实被保留；上下文变化或失败拒绝导航。正式保存再校验并捕获稳定表单，避免异步等待造成内容与提交基点错配。

这也保留了 Git 式操作顺序：连续编辑 → 本机保留/合法私有草稿 → 核对差异 → 明确提交。输入被保留不等于已推送、审核或发布；界面必须清楚显示层次。

## 展示与语义的边界

列宽仅为 Web 展示元数据。纯宽度改变不应修改字段类型、值域、源样本、人工意见或审核指纹，因此可以先保存；其他字段规则仍受本人草稿与活动任务保护。权重表达可分配空间的份额，不承诺在最小宽度、固定列和窄屏限制下每列始终占整张表同一百分比。

详情采用覆盖抽屉，避免选中一行就压缩表格或重新取数；表格内部滚动与移动端整页溢出分别验证。列宽属于分支字段配置，保存为版本化元数据；检查点则是本人本机恢复状态，两者不能混为同一“保存”。

JSON 结构化显示须保留原始文本入口。JavaScript解析可能改变大整数、浮点精度、指数写法或负零；不安全时使用原始文本。格式化显示下仅空白变化可能消失，查看原始模式才能核对字节层面的文本差异。

差异计算与渲染均设置限额。超限提示、粗粒度回退和上下文折叠是可见的性能边界，不能用空结果掩盖未完成比较。所有文本通过安全文本渲染，不把 Skill 包或样本中的内容作为指令执行。研究与浏览器证据只用合成内容。

## 实现映射

- `SampleFieldsPanel`、`sample-field-config`、`sample-field-checkpoint`：字段控件、宽度、无效表单保留与最新配置对照。
- `DatasetWorkbench`、`dataset-workbench-checkpoint`、`dataset-ui-state-client`：覆盖抽屉、原始输入恢复、导航持久化及多窗口 CAS。
- BFF `dataset-ui-state`、`dataset-fields`：身份隔离的本机恢复存储，以及正式配置的真实提交；两条路径权限和职责分开。
- `TextDiff`、`text-diff`、`CommitPanel`、`TabularDiff`：安全的行/行内差异、JSON原始入口和受限展示。

这些是本项目的实现选择。官方参考不为本地恢复流程、事务语义或全部 SaaS 等价性背书；是否通过以[R7实际证据](../implementation-r7.md)为准。
