# 标签层级与入口 UX 评审建议

状态：需求设计与粗原型评审，待用户确认。本文只读核对当前实现，不代表正式功能已经实现，也不授权修改应用、服务或数据。

## 1. 当前实现与需要明确的边界

- `LabelGovernanceView.vue` 已有组织选择、模板领域、维度库、草稿／不可变发布版本、缺项反馈和指定维护者；模板目前没有“数据集模板／样本模板”类型，一个模板的 binding 可以同时含 dataset、file、row scope。
- 组织治理权限与项目读取权分开；实例 owner 和指定组织维护者可维护目录，普通标注／复核人员仅消费授权项目的已发布规范。项目管理员不自动取得组织治理权限。
- `DatasetOverview.vue` 已按当前分支固定提交展示样本、人工标注、有效复核、附件、README 和最新 Release，但只显示标签维度数量，没有直接呈现当前数据集标签。
- `RepositoriesView.vue` 的卡片和搜索使用 `repo.tags` 自由文本项目关键词；它们来自仓库设置，尚不是 `scope=dataset` 的结构化标签。当前只有命名空间、访问范围、排序及关键词筛选。
- `ReleasesPanel.vue` 的 Release 与工作快照均有固定 commitId；正式发布资产不可替换。它们不应随当前浏览分支变化而显示另一版标签。
- `ProjectSchemaBinding` 目前只保存一个模板版本快照。两个模板消费入口若需要分别采用版本，不能仅改页面文案后假定已有两套独立绑定能力。

## 2. 建议保持一份数据集标签值

建议把“项目标签”“当前分支标签”作为同一份 **dataset scope 赋值** 的不同入口或读视图，不再复制出 project scope 和 branch scope 两份可写值。

| 用户看到的位置 | 实际含义 | 版本来源 |
| --- | --- | --- |
| 项目内“数据集标签” | 该分支整个逻辑数据集的标签 | 当前分支先解析为固定 commitId |
| 项目列表标签与筛选 | 数据集标签的默认分支摘要 | 配置的 defaultBranch 当前固定头，不硬编码 main |
| 分支或历史版本页面 | 相同标签在所选版本的状态 | 所选分支头或显式历史 commitId |
| Release 标签 | 发布时的数据集标签快照 | Release.commitId，不能读取最新分支替代 |
| 仓库设置中的自由关键词 | 原 `repo.tags`，属于项目检索关键词 | 访问策略／仓库设置，不自动转成结构化标签 |

分支本身是移动引用，不是独立标签 scope，也不是不可变版本。对两个分支分别赋同一维度，可以得到不同值；合并后依原版本控制和冲突裁决处理。项目卡片不保存第三份“最近一次手工输入”的标签。

数据集标签对负责人应呈现一份明确的生效结果；旧数据存在多操作者不同意见时，应显示“待确认／有分歧”，不能任取第一份、最后一份或多数值用于卡片与筛选。是否将数据集级写模型进一步收敛为负责人维护的单一权威结果，需要在实施设计时明确；不以增加另一份 project 值解决冲突。

## 3. 标签管理：组织、领域与两层模板

推荐组织和领域放在目录顶部，左侧表达模板层级，避免当前“模板／维度”与领域交错占据同一组导航。

```text
标签管理                     组织 [本组织 ▼]   领域 [全部领域 ▼]
规范目录                     搜索 [名称、说明、稳定 ID              ]
  数据集模板                 [模板列表]          [草稿 / 发布版本详情]
  样本模板
  共享维度库
  缺项反馈
  指定维护者（实例管理员）
```

- “数据集模板”定义整个数据集的维度，例如数据来源、任务类型、许可声明、适用领域。赋值作用于完整数据集，不自动批量写入每条样本。
- “样本模板”定义条目级维度及细粒度标注可使用的字段，例如人工判断、严重度、置信度、证据说明。文件标签仍保留明确的 file scope，可放在样本模板的“附件标签”子区；不新增第二份文件标签或把所有附件值混入 row 赋值。
- 两层模板复用同一个稳定维度库；稳定 ID、选项 ID、显示名、描述、弃用和历史版本规则不变。同一维度确实适用于两个层级时，可以在两种模板中引用同一个已发布维度版本，不复制定义。
- 本轮不要按中文名称或维度内容猜模板类型。现有混合 scope 模板应标为“兼容模板”，只读解释其适用层级；后续由维护者显式另存、发布并由项目负责人采用，不静默拆分已有版本。
- 领域是模板目录的分类条件，不等于样本风险类别或自动推断的数据集内容。组织切换后清空领域和已选定义；领域按该组织可见目录计算，不能向维护者暴露其他组织目录。
- 草稿只对可维护该组织的人开放；标注者／复核者不进入治理页。项目采用处只列该项目组织允许消费的已发布版本，不列草稿；弃用不破坏已有项目的固定快照。
- 若产品确认数据集模板与样本模板可独立采用，建议在同一项目规范快照中原子保存两个明确的模板引用及版本，不分别用两个没有共同基点的请求更新；旧单模板快照保持可读，不自动升级任务。

## 4. 项目内：当前分支的数据集标签入口

推荐在概览 README 侧栏增加“数据集标签”卡片，位置靠近当前版本信息；工作台顶部原“数据集标签”入口与此打开同一个赋值面板。

```text
数据集标签                分支 feature/review · 提交 7ac09e…
领域       AI 安全
来源       用户提交、合成数据
任务类型   安全评测
模板       通用数据集 v2                  [查看规范]
                              [编辑数据集标签]
```

- 标签卡片所有项目读取者可见；编辑需要数据集级赋值能力及任务／负责人策略允许。建议把维护整体数据集标签明确交给负责人；普通标注者仍编辑分配样本，不能借此更改整个任务的上下文。最终能力组合应与 BFF 一致，不能只根据笼统 `write=true` 露按钮。
- “查看规范”只打开本项目绑定快照，不把普通人员带入全局治理；“采用／升级模板”留在设置中，使用独立 schema.bind 权限，并遵守活动任务、兼容性和 CAS 检查。
- 值面板只消费该层级已采用模板。缺维度或选项时使用“反馈缺项”，不现场增加规范字段或自由创造选项。
- 页面始终显示真实分支名及固定提交摘要。历史 commit、Release 均只读；切换分支、样本、模板版本、身份或离开项目时，需要处理未提交草稿；取消切换应还原选择器。
- 模板选择／升级与赋值是两种动作，不在同一个“保存标签”按钮中隐式完成。升级不自动改变活动任务或已发布资产。
- 没有模板时显示“当前版本尚未采用数据集模板”；没有赋值时显示“尚未填写”；读取失败显示“暂不可用”；三者不能混成“没有标签”。

## 5. 项目列表：默认分支标签筛选与卡片

在现有关键词、组织／命名空间和可见性筛选下方增加结构化标签条件。页面明确说明：“标签按各项目默认分支最新提交展示”。“主分支”指项目配置的 defaultBranch，而非固定名为 main 的分支。

```text
项目 [关键词搜索                         ] [组织 ▼] [可见性 ▼]
标签 [数据集维度 ▼] [选项 ▼] [+ 添加条件]
已选：来源 = 用户提交 ×   任务类型 = 安全评测 ×        清除全部

项目名                                         私有
项目说明……
[来源：用户提交] [任务类型：安全评测] [+2]
样本 2,000             更新……       默认分支 main
```

筛选语义建议：同一维度多个选项为 OR，不同维度为 AND，与关键词、组织、可见性条件再做 AND。提供“未填写”条件；暂不可用或有分歧的标签不应被错误算入“未填写”。移除 chip 仅移除查询条件，不修改标签值。

候选维度与计数仅从当前身份有读取权、当前组织条件内的项目计算；跨组织同名 ID 不能混为一个维度。筛选标识应包含组织和稳定维度／选项身份，显示采用中文名称；显示名变更不能改变旧链接含义。没有可靠语义映射时，不自动把不同组织的“来源”合并为同一个筛选。

卡片优先展示模板中明确指定用于目录检索的少量单选／多选维度，最多三条 chip 后折叠“+N”；完整值和来源版本在详情可见。长文本证据不直接塞满项目卡片。旧 `repo.tags` 如继续保留，应单列“关键词”，不能混成同一套结构化标签或双向同步。数据集级“风险类别”与样本级“人工判断”分开，不以存在敏感数据推定恶意。

后端应返回已鉴权的固定默认分支标签摘要及其 commitId；列表缓存键包含身份与默认分支头。页内不得因遍历所有样本才迟迟加载卡片，也不能默默使用旧摘要当最新值。只有实现后经完整分页／筛选校验，才能承诺按全量项目过滤；粗原型展示应标明示例数据。

## 6. 发布页与历史版本

Release 详情展示数据集标签和两层规范版本，明确“发布快照”及 commitId；它们与该资产包来自同一个固定版本。查看旧 Release 时，当前分支改变不得刷新出新标签。Release 对比应说明数据集标签／规范是否发生变化；发布后想改标签，需要新的提交和新 Release，而不是覆盖旧资产。工作快照显示“未代表完成复核”，不以现有风险标签伪装成已审核。

## 7. 所有表格的文本垂直居中

统一要求适用于数据集表格、项目列表、模板／维度列表、任务、发布资产、筛选结果以及弹窗表格：`th`、`td` 使用 `vertical-align: middle`；以 grid／flex 实现的表格行及单元格使用 `align-items: center`。这指**垂直方向**，不要求正文、数字或字段名全部水平居中；文本仍左对齐，数值可右对齐。

单元格出现多行描述、标签 chip、图标、复选框或操作按钮时，整体内容组在行高内垂直居中，按钮和复选框也居中；避免某列顶部对齐而另一列中心对齐。长正文在居中的内容组中按行高换行或截断，完整内容通过明确展开查看。建议基础行高至少44px，含双行说明可增高；不要通过极小字体或无序压缩达成密度。

当前 `DatasetWorkbench.css` 的数据格存在顶部对齐，`style.css` 的 `.preview-table th` 也有 `vertical-align: top`；未来实施需覆盖这些既有规则并核对 sticky 列、表头、表格预览和响应式布局，不能只给新页面设置居中后宣称全站完成。本轮未改样式。

## 8. 工作台意见归属的现有可理解性问题

只读核对：`DatasetWorkbench.vue` 的 `labelValues()` 先取合并 `labels.assignments`，再覆盖当前 actor 的独立记录和未保存草稿。因此“当前 actor 尚无记录”时，表单仍可显示 owner 或他人的现有标签值；页面当前只写“独立保存每位标注者的意见”，没有明确标出“我的意见未填写，以下是参考意见”。查看本身不会变脏，但修改任一字段会把当前表单的合并值加入该操作者草稿，容易让人以为此前已亲自填写。

`canAssign` 当前只依据项目赋值能力与历史只读状态，没有在页面按所选条目的本人任务范围禁用控件。因此 B 可以在自己的分支看到不属于自己的 qa-1 的 owner 旧证据和赋值表单，保存时 BFF 会拒绝任务越界；这是 UI 可理解性差距，不等于已绕过服务端权限。

建议后续确认：将“我的意见”与“现有／已复核参考意见”分开；当前 actor 无记录时明确显示未填写，不把别人的结果当成已完成的个人表单。若允许复制，应使用“采用参考意见为我的草稿”明确动作。任务外条目可只读浏览并显示“此条目未分配给你”，提供“只看我的任务”入口；不能等点击保存才首次说明范围。数据集标签、样本标签与独立意见的归属都需要一致文案。本轮不改这段实现，也不改任何现有值。

## 9. 确认项

建议在开发前确认：两层模板是否独立采用发布版本；项目标签是否统一复用当前分支 dataset scope；列表是否固定按默认分支标签检索；数据集级赋值的负责人权限组合；卡片默认展示维度；旧混合模板和自由关键词的兼容呈现。确认前只做示例粗原型，不迁移标签、不创建第二份值、不改变当前规范和任务。
