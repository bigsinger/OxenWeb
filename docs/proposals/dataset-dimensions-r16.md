# R16：安全样本库四维组织与评测纪律

日期：2026-11-09。依据负责人本轮设计与确认，`purposes` 多选，其余三项单选。本文件区分数据设计、当前实现与后续能力；实际落地和验收见 `docs/implementation-r16.md`。不修改官方 Oxen 0.67 服务端、内核或冻结 OpenAPI。

## 最小字段

字段值使用稳定英文 ID，界面提供中文释义。未分类为缺失或 null；不会自动填成 train、普通或公开。项目样本字段定义与其取值分别维护。

|字段|含义|默认选项 ID／中文|规则|
|---|---|---|---|
|`split`|本划分版本的训练／调优／测试角色|`train` 训练、`dev` 开发调优、`test` 测试验收|单选；同一稳定样本只能有一个值；同源组整体分配|
|`quality`|答案与依据的审核质量|`normal` 普通、`gold` 金标|单选；金标不代表独立、未知或保密；仍须有效独立复核证明|
|`purposes`|业务使用目的|`training` 训练、`regression` 回归、`smoke` 冒烟、`evaluation` 常规评测|多选；可回归＋冒烟；用途不替代 split|
|`visibility`|交付／访问要求|`internal` 内部、`hidden` 隐藏、`shared` 指定分享、`public` 公开|单选；取值本身不授予访问、下载或分享权限|

风险分类、攻击方法、来源、严重性继续由独立标签模板维护，不能塞进上述四字段。系统行 ID、来源记录、源答案与人工结论也不混用。

## 项目、分支、字段与集合

|层次|职责|实施边界|
|---|---|---|
|项目／仓库|同领域、同访问边界的受控主库|当前四个真实项目继续保留；不按金标／回归再复制成独立主库|
|分支／提交|多人协作及数据修订版本|分支不是 train/dev/test；正式集合固定提交，不能引用不断变化的 main|
|四维字段|描述样本的角色、质量、用途和访问要求|全局规则目录、项目采用的版本化字段配置、样本取值三层分开；项目不随全局编辑改写历史|
|动态筛选|日常检索与标注工作列表|条件变化会改变结果，不等于已冻结基准|
|固定评测集合|记录固定成员、样本修订、答案和评分规则版本|本轮由 Release 的四个固定视图与 manifest 保存；样本可同时进入子集和全集，不复制后独立修改。任意集合编辑页面及评测结果存储属后续能力|
|Release／分享包|交付固定版本和经过权限核对的子集|遵守“是否导出”；不包含未授权样本、原始全库归档、历史或无关附件|

Oxen 当前固定契约未验证到原生机器学习 split 能力，因此此处是 Web/BFF 的结构化字段扩展，不假设存在上游 split API。Hugging Face 支持在同一仓库按文件／目录配置 split，但不因此获得行级权限；这只能作为组织方式参考。[官方说明](https://huggingface.co/docs/hub/datasets-file-names-and-splits)

## 筛选与冻结

|集合|示例筛选条件|冻结与交付|
|---|---|---|
|开发回归集|日常内部筛选为 `split=dev AND purposes contains regression`；当前外发 Release 再要求 `visibility in(shared,public)`|固定来源提交、稳定行 ID、内容摘要、已采纳答案及其摘要；历史缺陷／案例关联由受控说明维护。可与人工冻结的冒烟集合重叠；当前固定金标测试和开发回归因 split 不同而互斥|
|金标测试集|`split=test AND quality=gold AND visibility in(shared,public)`|必须核对独立复核证明有效；冻结答案、评分规则版本及清单摘要；不把标为 gold 等同完成复核|
|隐藏验收集|`split=test AND visibility=hidden`，正式验收通常再要求 `quality=gold`|固定未披露对象名单和曝光记录；独立私有项目优先；只交付给授权验收人|
|指定分享集|`visibility=shared` 加用途／split 条件|按明确受众建立固定发布包，保留内部来源关系；分享包不带完整主库或隐藏成员索引|
|非隐藏评测包|`visibility in(shared,public)` 加 `purposes contains evaluation`|不会因为“不是 hidden”就把 internal 样本自动放进对外包；按授权交付|

正式集合记录至少包含：集合 ID／版本、源项目与提交、筛选条件、逐项稳定行 ID 与内容摘要、采纳答案摘要／版本、评分规则 ID／版本、创建人和时间、集合整体摘要。没有评分规则版本的工作快照只能称工作快照，不能称完整可复现实验。重新筛选产生新集合版本；不覆盖旧成员及旧结果。

本轮的具体落点是：Release 控制记录保存发布 ID、版本、创建人和时间；包内 `manifest.json` 保存固定视图、成员、提交／内容摘要、采纳答案摘要、内置筛选规则版本，以及单个受控标识 `scoringRuleVersion`；文件校验表和发布资产 SHA-256 固定包内容。当前不内嵌外部评分规则正文，也不运行评分器或保存实验结果；团队须在受控版本文件中另存评分规则及运行证据。跨团队接收对象名单、历史缺陷关联和完整披露登记也需人工维护；现有持有者分享链接不是指定自然人账号绑定，项目内共享发布曝光索引不能代表完整的外部接触史。

## 隔离与泄漏规则

|规则|执行方式|
|---|---|
|同一划分版本内 train/dev/test 互斥|稳定行 ID 唯一；对来源、事件、模板与高度相似变体先建同源组，再按组划分；跨项目也核对|
|同源变体不跨 split|复用 R14 检查结果作为候选证据，人工处理未解析配对、共享敏感实体和 Skill 成员；不把“算法未发现”写成无泄漏|
|质量不替代独立性|gold 必须经过严格审核；仍可能来源公开、模板重复或被基础模型见过|
|隐藏不替代未知泛化|未知攻击评测另设来源／时间／攻击家族留出；不能仅筛选 hidden 得出未知泛化结论|
|访问按真实边界执行|当前没有覆盖原始文件、历史与 Oxen 直连接口的可靠行 ACL；隐藏集优先独立私有项目，算法／QA 继续只接收发布包|
|曝光不能撤销|完整向被测团队开放后记录披露对象／时间／发布版本，下一版隐藏集补充新样本；原样本可转入 dev／回归，但保留原测试记录|
|调优污染不回写历史|反复用于调优的 test 在新划分版本中调整角色，补充独立 test；历史评测继续引用旧提交和规则|
|重叠集合不重复计总分|回归、公开和隐藏单列报告；显式报告交集，避免把重复样本当成独立权重|

按组划分用于减少相关样本在训练与测试同时出现，属于可验证的一般方法；具体同源定义仍由领域规则决定。[scikit-learn 分组交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)。安全评测中练习与保密正式评测的分离可参考 [MLCommons AILuminate](https://mlcommons.org/ailuminate/safety/)，本项目不直接复用其数据或声称获得其认证。

上述流程纪律不等于全部自动执行。当前发布验证稳定身份、已填写的已知 family、有效复核、项目内发布曝光和附件摘要；跨四库语义同源、未披露对象的完整接触史、证据是否充分以及评分正确性仍由负责人核对。

## 小团队流程

|环节|输入与动作|输出／负责人|
|---|---|---|
|入库|保存原包、生成稳定 ID、保留来源／许可；Skill 单样本 ZIP 作为惰性附件|可信主库；导入人员|
|初步标注|标注员使用业务模板，补齐答案、理由和必要证据|待复核的样本与业务标签；标注人员|
|同源核对与四维确认|对跨四类数据建族；按组确定 split，并确认 quality、purposes、visibility，提交后再进入最终独立复核；未解决项暂缓|包含四维值的新样本版本与同源清单；负责人。gold 此时仅为待复核的质量声明|
|最终独立复核|核对包含四维取值的完整版本，以及答案、理由、必要证据和领域金标标准|对当前内容哈希有效的采纳结论与审核证明；独立复核人员|
|评测冻结|选择四维条件，核对权限／曝光／有效复核，冻结成员和规则|固定集合与不可变 Release；评测负责人|
|执行与报告|按集合版本运行，不在测试中动态换成员／答案|独立的回归／公开／隐藏报告|
|披露与回流|登记完整披露，保留原结果；在新版本转 dev 或回归|追加曝光记录、下一版隐藏补充计划|

四维取值属于源记录内容，修改任何一项都会改变内容哈希并使先前的标注／复核证明失效。因此先确认四维值再做最终独立复核，可避免重复审核；复核后因披露、用途调整或重新划分而改值时，仍须重新核对和复核新版本。填写 gold 不等于已经获批，发布门禁继续核对有效证明，不为分类操作提供指纹例外。

|必须建设／执行|后续可选能力|
|---|---|
|四维独立字段、全局规则目录、类型和选项校验；项目版本化采用；已有值不覆盖|更细领域的可选字段模板和规则版本迁移向导|
|已有草稿→提交→复核→Release 链路，显式固定提交；字段导出控制|独立集合管理界面、评分执行器、自动统计与实验追踪联动|
|稳定 ID、来源保留、同源人工核对与按组划分；R14 问题解决前不真实分配|持续跨项目近似检测、翻译／改写／语义变体分析|
|私有主库、发布包受众控制、隐藏优先独立私有库、披露记录|覆盖搜索／API／原文件／下载／导出／历史的全面行级权限；未完成前不可宣称支持|
|固定集合成员清单、答案版本和评分规则版本（可先使用受控版本文件）|自动生成的多集合评测报告与重叠去重统计|

## 本轮真实项目操作边界

本轮已给四个已导入项目补齐四字段定义，复用已有的 `split` 及现有取值；全量核对 6,719 条记录未变，实际回执见[实施记录](../implementation-r16.md)。未把 R14 金标／回归／隐藏候选翻译成新的字段值，未覆盖来源原有 train/dev/test，未自动声明 gold，未移动隐藏样本，未发布或分享真实数据。新增字段缺失值继续留空，待负责人确认实际成员与审核质量后再赋值。
