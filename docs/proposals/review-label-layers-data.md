# 标签分层：当前实现核对与数据兼容建议

日期：2026-11-08。状态：只读设计评审，待用户确认；本文不代表已实现。仅核对源码与既有设计文档，未读取真实样本正文、修改服务、测试或四个数据集。

## 1. 当前实现到哪里

| 项目 | 实际支持 | 当前限制 |
| --- | --- | --- |
| 数据集标签 | `scope=dataset`，不含文件路径或样本 ID；每个操作者独立记录，有冲突、历史与审计 | 与文件、样本共用一份列定义和一个项目模板 |
| 分支与版本 | 赋值、`.oxenweb/schema-binding.json` 均在仓库提交中；读取先固定 commit，新分支继承基线，可独立演化 | 页面上叫“项目标签模板”，容易误解成整个项目各分支实时共享 |
| 组织规范 | 维度与模板有草稿、不可变发布版本、弃用选项；项目显式采用固定版本及完整快照 | `TemplateDraft` 没有数据集/样本类型，只有 domain 与逐维度 scopes |
| 文件标签 | `scope=file` 且明确 path，支持样本表及附件；片段/步骤不能写到 file 层 | 不能因简化成两层而把旧文件标签改成样本标签 |
| 样本标签 | `scope=row`，稳定 rowId，逐人保存；片段/步骤有源定位与 hash | 表单只按 scopes 筛列，无法区分宏观管理字段、样本结论与片段字段 |
| 规范消费 | 项目模板选择可按 domain 筛选；治理页有组织切换与领域导航 | 消费接口只返回 `namespace` 所属组织；跨组织绑定明确拒绝。筛选其他组织不能直接等同于获准采用 |
| 复核 | 绑定快照、内容、标签、片段/步骤、上下文标签、实际附件字节共同约束旧审核有效性 | `templateHash` 包含整份 columns 与 binding，尚不能独立比较数据集模板和样本模板 |

主要依据：`packages/shared/src/governance-types.ts`；`apps/server/src/{governance,labels,dataset,dataset-storage,workflow,releases}.ts`；`apps/web/src/{views/LabelGovernanceView,components/SchemaBindingPanel,components/DatasetLabelFields,components/DatasetWorkbench}.vue`。

## 2. 为什么样本表单显得宏观

`label-templates.ts` 定义了 37 个不同维度，组成六套预设。37 是所有领域合计的维度池，不是一套必须逐样本填写的标准。通用为 6 个，安全基础为 15 个，敏感数据/提示词注入分别 20 个，Skill/行为偏离分别 21 个。

`data_source`、`task_type`、`dataset_split`、`risk_category` 等目前明确允许 dataset/file/row；`DatasetLabelFields` 据此原样显示。`DatasetService.read` 又用一个 binding.snapshot.columns 整体替代旧 columns。因此这属于模板语义和模型层合并，单纯折叠控件不能解决。

治理页已有组织与领域两个控件，问题不是完全没有筛选，而是缺少“模板用途”这个独立维度，以及项目消费页缺少清晰的组织来源与授权范围。

## 3. 两套主要模板与一个兼容层

建议增加明确的模板用途 `targetKind: dataset | sample | file`。常用界面只突出“数据集模板 / 样本模板”；file 用于附件兼容与需要单独管理文件的项目，不要求每个项目再配置第三套模板。

- 数据集模板：描述当前分支数据集的来源、用途、授权、规范、领域覆盖、共有基线等整体属性。赋值保留 `scope=dataset`，不对每条样本复制值。
- 样本模板：记录单个样本人工判定、该领域特征、严重度、置信度、证据、预期与观察行为。持久化仍使用 `scope=row`，避免因产品名称改成 sample 而重写旧身份和路径。
- 文件兼容层：保留原 `scope=file` 及路径语义；没有显式文件模板时，用旧文件规范快照显示已有字段和值。负责人可选择采用文件模板或制定映射，不从 dataset/sample 模板猜测、不搬移附件标签。
- 维度仍在组织目录复用；模板用途是强约束，不再让模板随意跨 dataset/row 勾选。确实共用含义的维度可被两套模板引用，但赋值、必填约束与复核用途独立。
- 样本模板内部可再声明字段适用于“整条 / 片段 / 步骤”；默认仅整条。现有片段/步骤记录保持原义兼容，不因其同属 row 自动把全部宏观字段塞入片段编辑器。

建议 v2 绑定继续使用同一路径和一次 CAS 提交，但结构变为：

```ts
type Layer = 'dataset' | 'sample' | 'file';
type LayerBinding = {
  organizationId: string;
  templateId: string;
  templateVersion: number;
  checksum: string;
  snapshot: PublishedTemplateSnapshot; // 增加 targetKind
};
type ProjectSchemaBindingV2 = {
  version: 2;
  layers: { dataset?: LayerBinding; sample?: LayerBinding; file?: LayerBinding };
  legacy?: { sourceChecksum: string; migrationId?: string };
  boundAt: string;
  boundBy: string;
};
```

物化快照应提供 `schemasByScope`/`bindingsByLayer`，保存根据目标层验证；兼容汇总 columns 只用于旧消费者，不能作为新权限或必填判断依据。同名但语义不同的跨组织维度必须显式映射或拒绝冲突，不能按中文名合并。

## 4. 领域和组织独立筛选

模板目录的筛选轴为“用途 / 领域 / 所属组织 / 搜索”。领域不是组织的下一级，也不隐式决定访问权。默认显示当前项目所属组织、当前用途；切换组织保留仍有效的领域筛选，结果显示来源组织、固定版本、维度数与授权状态。

当前安全边界继续保留：组织规范管理权不包含读取私有样本，项目权限不包含管理整个组织。只枚举当前身份有权看到的发布目录；不可见的私有组织连数量也不泄露。

第一版跨组织复用建议采用显式“另存到当前组织草稿 → 负责人发布 → 项目采用”，保留来源模板和版本，不放开当前跨组织绑定检查。若产品要求直接共享绑定，需另设计模板分享授权与撤销策略，不能靠前端组织下拉框实现。

## 5. 37 个旧维度如何处理

以下是新默认编排，不是对已有赋值自动迁移的命令：

| 维度池 | 个数 | 新默认位置 |
| --- | ---: | --- |
| data_source、task_type、annotation_guideline | 3 | 数据集上下文；已有逐样本差异继续保留为样本上下文 |
| 安全基础的基准引用、人工判定、风险类别/来源、严重度、置信度、预期/观察、证据 | 9 | 样本模板；数据集“风险覆盖范围”若新增应有自己的语义键，不能冒充某个样本的风险结论 |
| 敏感数据 5、注入 5、Skill 6、行为偏离专项 4 | 20 | 按领域进入对应样本模板，不把所有领域的 20 个字段同时强加给每条记录 |
| dataset_split、review_note、drift_baseline_goal、drift_baseline_version | 4 | 依据项目上下文配置；共有基线可放数据集，存在逐条差异则保留样本字段；划分不能仅按第一条样本提升为全数据集属性 |
| review_status | 1 | 旧手工字段保留可追溯；系统任务状态由真实任务/复核服务计算，不由此标签代替 |

迁移必须先生成不含正文的预览：原维度 ID/semanticKey、层级、类型、选项映射、各层非空赋值数、冲突数、影响任务数。按稳定语义键和明确映射判断，不能按显示名或“刚好 37 个”判断。

原则：

1. v1 单模板先只读适配成各层视图，旧赋值位置、操作者、值、fingerprint、快照与历史不变。不在读取时持久化迁移。
2. 移除默认表单的字段仍在“历史/兼容字段”显示与导出；不得通过换模板把已有值隐藏到不可检索。
3. 行级宏观字段若全体相同，仅提出“提升为数据集属性”候选；需负责人显式确认、记录来源与映射，原行记录保留审计。有差异则继续行级表达，不选第一条、不投票猜测。
4. 选项 ID、legacyValue、空值、不适用与未知分别映射；不认识的值进入可见的待处理列表。无法兼容的类型或必填变更阻止采用，不静默清空。
5. 原 JSONL、业务 ID、原始 ground_truth/label/label_name/review_status 等源字段处于 `data.*`；人工值处于独立标签命名空间。此次分层不改基准真值、不写回原始正文、不把系统审核结果覆盖到同名源字段。
6. 显式升级使用 expectedCommit 一次提交绑定、迁移清单及必要覆盖记录；CAS 失败保留草稿，不部分提交。旧 commit 继续按旧格式读取，撤销采用新提交，不改历史。

## 6. 版本和复核失效规则

模板发布与分支采用继续分离。目录发布新版不自动改变项目、工作分支或活动任务；任务固定其采用的样本模板版本与快照。每层页面都显示当前分支、commit、模板版本，历史 commit 禁用修改。

| 变化 | 建议处理 |
| --- | --- |
| 数据集模板的名称、说明、布局变化，实际上下文值未变 | 不应仅因整份绑定变化而让所有样本审核失效；绑定可追溯，显示变化与语义变化分开比较 |
| 数据集/关联文件的实际上下文值改变 | 对依赖该上下文的样本重算证据摘要，旧审核显式失效；字段默认先按保守相关性处理，不能为了减少失效排除真实证据 |
| 样本模板维度、选项含义、必填、适用范围改变 | 升级前显示影响；活动任务保留固定版本，或显式撤销/重新分配；不能自动让旧审核按新语义通过 |
| 只新增可选项 | 旧选值仍有效；新选择必须基于显式采用的版本，不能读取目录最新版临时扩充 |
| 正文、稳定身份对应内容、片段/步骤锚点或关联 ZIP 字节改变 | 内容/源 hash 和实际附件 SHA 校验继续使相关旧审核失效；不信任源记录自报 SHA |
| dataset/sample/file 两层或三层出现未处理的独立意见冲突 | 显式裁决或阻止正式发布，不能在分层时顺便选一位操作者 |

需要把当前 `templateHash({columns,binding})` 改为样本任务依赖的语义快照，另保留完整绑定审计 hash；上下文实际赋值仍参与 review fingerprint。若尚未定义安全的展示/语义分离 checksum，则所有规范变更仍保守要求重新确认，不能跳过审核。

## 7. 工作台和完整导出

概览页显示 README 与数据集元信息摘要；“数据集标签”抽屉编辑数据集层并显示其固定模板版本。样本右侧默认显示当前领域样本模板，数据集上下文是只读摘要，可展开查看，不要求重复填写；附件仍可打开文件标签。权限沿用数据编辑、标注赋值、复核、规范绑定、规范管理的职责分离。

搜索继续明确区分 `data.*`、`dataset.*`、`file.*`、`label.*`、`span.*`、`step.*`、`workflow.*`，保留旧查询兼容别名；不把数据集上下文自动覆盖成 row 值。筛选条件与统计必须基于整个固定版本数据集。

Release 包的 schema 中应包含各层模板完整快照、组织/版本/校验和、兼容映射；labels 保留各层目标、逐人意见、已采纳结果、片段/步骤和历史证据。样本可用文件、README、附件、来源、固定 commit 与校验清单继续完整输出。再导入保留稳定 rowId 与真值；外来审核证据保留 provenance，不冒充本机已审批状态；采用其模板仍受当前组织权限约束。
