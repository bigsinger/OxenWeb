# R21：每个项目只保留当前发布

日期：2026-11-10，Asia/Shanghai。用户明确采用单一当前发布，取消保留旧发布及其下载。这是本地 Web/BFF 扩展，不修改 Oxen 内核、分支或提交历史。本轮没有新增 SaaS 观察。

## 当前界面

| 位置 | R21 行为 |
|---|---|
| 项目 → Releases | 分为「当前发布」和「待发布候选」，工作快照仍在独立子页 |
| 创建 Release | 版本号、来源分支／提交、标题和自动变更说明；移除预发布选项及其请求参数 |
| 数据与变更检查 | 比较唯一当前发布，展示样本、附件、导出字段及样本／文件增改删；保留确定性自动说明和人工编辑 |
| 核对并发布 | 明确确认“替换现有已发布版本，并让旧下载链接和分享链接失效”；分支及提交历史不变 |
| 发布完成 | 自动成为唯一当前发布，不再要求或显示“设为最新稳定版” |
| 项目概览 | 直接显示唯一 `status=published` 的版本；空状态为“尚未发布数据集，可前往 Releases 创建并发布版本” |
| 版本详情 | 显示本版固定内容及替换前比较基线的版本／提交元数据，不依赖被删除的旧发布详情 |
| 清理待核查 | 当前已发布版本若 `cleanupPending=true`，明确说明新版已发布、旧链接已失效，但旧文件清理尚未完成；联系管理员核查，不提供无效的清理按钮 |
| 历史兼容界面 | 不再有 `legacy`、旧只读发布、旧资产或旧模板的展示分支 |

候选保存、校验打包、正式发布、工作快照、权限与草稿保护沿用现有操作；自动说明的手工修改在重新检查和 CAS 冲突后继续保留。发布创建／更新请求只包含当前版本、来源、说明及提交／基线／摘要 CAS，不发送 `prerelease` 或手动 `latest`。

后端负责耐久替换旧发布记录、资产与分享链接，并保留冻结的比较证据。前端文案不能代替字节清理或权限校验；完整存储验收见主任务记录。

撤回确认说明将移除当前发布及其文件，项目将暂无当前发布；分支及提交历史保留。不会承诺恢复旧发布或旧链接。
