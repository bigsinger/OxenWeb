## 如何持续维护

已有记录能回答的问题直接复用。遇到缺口时，仅核对相关页面，追加一条记录：日期/URL/角色/前置状态/动作/可见结果/截图与 DOM/对应本地组件/尚未证实的行为。截图和 DOM 用 `captures/YYYY-MM-DD/` 保存，保留旧版本；动作应能被另一位开发者复现。

每次观察后同时更新 `interaction-catalog.md` 或 `page-map.json` 的对应项。实现调整单独记入映射和验证，不改写历史截图。密码、令牌、Cookie、临时签名和真实私有记录不进入知识库；下载链接的签名参数须脱敏。

界面开发后以实际页面核对：入口位置、术语、动作顺序、上下文、加载/空/错状态、版本与权限、键盘和窄屏可用性。代码存在和类型检查成功不能冒充页面已观察。项目根 [AGENTS.md](../../../AGENTS.md) 已把这个工作流设为后续 UI 任务的入口。

## 已知不能推定的结论

- SaaS 非空分支比较持续显示上游错误页；没有据此猜测完整云端 MR 审批或评论语义。本地独立 MR 流程有自己的真实验证。
- SaaS 部分提交摘要报错，单文件结构化 diff 可用，两者分开记录。
- 原生权限、默认分支、重命名/删除在 SaaS 仅观察，未执行云端写操作。
- 自定义单选/多选标签及 dataset/file/row 三级标签是用户要求的本地扩展，不能从 SaaS 普通数据列菜单推导它们。

当前本地扩展另见[R6字段与修改状态验收](../../implementation-r6.md)：卡片一致筛选、版本入口简化、类型字段设置和红绿会话标记。此记录与冻结SaaS事实分开，后续调研可先复用其设计及验收结论。
