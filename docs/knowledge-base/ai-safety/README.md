## 必须保持的语义

一个 Skill ZIP 是一个样本，对应 `data/samples.jsonl` 一行；包内成员只读展示，不能当作待安装技能。原包、逐包SHA、原 `_expected.json` 与行清单中的原真值均保留。26个嵌套ZIP作为不透明成员保存，不自动展开。

敏感数据存在不等于恶意意图；攻击输入存在不等于攻击成功。源真值、人工判定、预期行为、观察行为、审核进度、置信度分别记录。新导入数据的人工条目标注保持空白，模板不会自动给出安全判断。

R1/R2 已取代早期“在打标页自行改列”的交互：组织管理员或指定维护者在全局标签管理中另存预设、维护维度和发布不可变模板版本；项目负责人采用固定版本，标注人员只消费这些字段，缺项走反馈。模板升级必须显式执行，不能改变活动任务的规范。正文覆盖、三级人工赋值、字符片段和步骤均按稳定身份保存，保护 `expectedCommit`、权限与草稿；内容、ZIP 实际字节或规范变化会使复核失效。历史文档中的旧列管理界面仅作旧轮证据。

README 在概览，选分支后数据编辑直接显示完整样本，无需选择物理 `data/` 路径。任务在独立分支执行，复核证据随真实提交保留；正式 Releases 从通过校验的主分支固定提交构建，工作快照不提供审核背书。详见 [R1/R2 实施记录](../../implementation-r2.md)及[整合方案](../../proposals/dataset-labeling-workflow-v2.md)。

R5起，卡片、项目顶部和概览的项目标签始终读取main的一份分类，不随工作分支或历史样本视图切换；“保存标签”只提交项目元数据。样本编辑、独立意见、任务和复核仍按分支隔离，样本草稿继续显式保存与正式提交。复制样本创建新身份，不能把原人工标注或审核状态当作新条目的既有结论。

四真实项目已用新模板明确填写各自研究主题，aisec关键词与主题在卡片可见。初始化逐库只写一份项目标签文件，6719条源JSONL完整SHA不变；提交与回执见[R5验收](../../implementation-r5.md)。这些主题表达集合用途分类，不代表每条样本的恶意判断或复核状态。

来源与基线可以随样本不同而变化；不要强迫所有条目共用同一个出处、目标或技能审查建议。层级以列的 `scopes` 为准，源字段只读展示与可编辑标签要清晰分开。
