## 用户行为与实现

数据编辑中，“人工标签”紧跟当前可见的精确`id`源列，其他源列保持项目既有排序。若id不存在、被项目隐藏或被个人列选择隐藏，人工标签回退到序号之后。`DatasetWorkbench`的colgroup、thead和tbody共享`datasetPresentationColumns()`同一顺序；列宽总量、权重、系统时间/操作人及评测列的尾部顺序不变。

标签单元格继续提供编辑按钮和双击入口，打开目标样本的类型表单；正文单击仍可复制，序号负责详情。移动列不改变当前身份意见、私有草稿、任务/权限或提交流程，不将人工作业标签混成评测用途字段。

项目设置 → 样本字段的“一键自动适配样本字段宽度”，从**当前表单**中筛选`visible !== false`，包括未保存的展示勾选变化。省略visible继续默认展示。左侧搜索只过滤配置列表，不改变适配范围；未配置但可展示的字段也参与。

现有BFF按请求的fields子集抽样及逐列估算，前端只发送参与字段。因此隐藏字段不进入测量、返回建议的应用或撤销快照，原宽度及enabled保留。全部隐藏时不发请求，按钮禁用并说明先勾选展示字段。撤销只恢复本次参与字段的宽度，不回滚展示、导出、排序等独立选择，也不覆盖未参与隐藏字段的后续手动宽度。自动适配仍先填建议，明确保存才提交字段配置。

改动文件：`DatasetWorkbench.vue`、`dataset-presentation-columns.ts`、`SampleFieldsPanel.vue`、`sample-field-config.ts`及两项合成回归文件。没有新增依赖、业务实体或后端协议。

## 分层方案解释

当前每类现有项目各一份受限私有主库，以稳定rowId关联独立评测管理元数据：范围shared/holdout/未分类互斥，gold/regression用途可交叠，与源truth及风险/来源等人工标签分开。分支用于编辑协作；Release从固定提交导出金标、回归、非隐藏全集和独立隐藏资产。共享表示交付范围，主库保持私有。

现有“算法/QA只下载发布包”条件下继续采用同项目主库，避免多份可编辑副本漂移。若以后要让这些团队读取主库，则应拆出有独立访问边界的隐藏项目/存储。公开实践、现实现证据与适用场景见[研究说明](research/dataset-partition-storage-r15.md)，不将离线候选或字段值当作仓库权限，也不把R14成员当作已确认写入。
