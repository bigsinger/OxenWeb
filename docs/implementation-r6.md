## 样本字段配置与编辑

项目设置新增“样本字段”，随当前样本分支版本化维护。配置支持 ID、显示名称、帮助、string/number/integer/boolean/array/object、有限单选及数组多选、可空和必填。选项保留原始 JSON 类型，不将数字或布尔转成字符串。字段可缺失、值为 null、false、0、空字符串或空数组，分别处理。

本地接口 `GET/PUT /api/repos/:namespace/:repo/dataset/fields` 使用 `schema.bind` 权限及 `expectedCommit`；PUT 为配置完整替换，校验完整已有逻辑样本。冲突返回数量及最多100条字段/稳定条目ID摘要，不含正文。新增逻辑列不会填充默认值或重写原样本；已有字段不能借此重命名或自动转换。无变化不产生提交，有效保存只写 `.oxenweb/dataset.json`。

本人当前分支有私有草稿时，需先提交或导出处理；项目有活动标注任务时不能修改字段规则。权限、分支头和这些条件在提交前复检。字段定义纳入草稿和审核指纹，避免旧规则静默套用。身份、来源证据、既有源真值及对象保留字段继续只读。解析器现保留源记录真实 own key，不静默省略；新建对象保留字段明确拒绝。

编辑器根据配置显示文本、数字输入、布尔勾选、单选和多选；缺失或 null 有明确状态控件。完整 JSON、追加、草稿保存和正式提交受同一校验约束。未配置字段沿用实际值类型，结构化值保留 JSON 编辑能力。研究来源与采用边界见[字段编辑设计](research/typed-field-editing-2026-11-08.md)。

浏览器实际通过：配置 enabled 为布尔、priority 为 normal/high 单选、categories 为 alpha/beta 多选、score 为整数，并新增 review_note 逻辑列。保存成功后删除仍被12条样本使用的 normal 选项，会显示12条冲突且不生成提交，输入保留。见[字段设置](evidence/r6-typed-fields/field-settings.png)、[冲突摘要](evidence/r6-typed-fields/field-conflicts.png)。

## 本次页面会话的红绿状态

- 红色：相对草稿基点有未提交修改；保存私有草稿仍为红色。文字徽标、前后值提示及状态图例辅助颜色，选中行不会遮住修改标记。
- 绿色：本次组件会话中明确提交成功的字段和行；失败不记录成功状态。后续编辑红色优先，改回当前基点会移除相应红色。绿色表示已提交，不表示审核通过。
- 刷新版本、重新加载或切换上下文会清除绿色，不持久化会话颜色。私有草稿若仍存在，重新载入仍能准确显示其未提交修改。
- 源字段、人工标签和片段/步骤的变化分开比较，标签变更不染红所有正文。前后值提示有长度和结构限额，大对象不整段拼入 DOM title。

为准确撤销已保存的修改，私有草稿查询提供当前页基点值及本人标注基线。取消 update/assign 后回到基点，不回到旧 overlay。全部撤销后仍可保存以清空磁盘草稿，不能误提交旧操作；细粒度标注与普通赋值一次合成后再检查空操作。
