# R5 项目统一标签与样本编辑

日期：2026-11-08。范围为用户追加的项目标签简化、表格行内编辑、复制与删除体验。全部改动位于TypeScript Web/BFF；官方Oxen 0.67 server和内核不变。复用冻结SaaS知识库，本轮没有新增SaaS观察，以下均为本地实现与验收。

## 项目标签

项目卡片、顶部和概览统一读取 **main的一份项目标签**。选择工作分支、样本或历史提交不会切换这份分类；样本正文、人工意见、任务和审核仍按其工作分支/固定版本处理。

顶部明确显示“编辑标签”；没有 `dataset.assign` 的人员只读查看。面板本地选择后点击“保存标签”，通过独立 `GET/PUT /project-labels` 保存main标签记录，不经过样本草稿接口。保存后只更新项目标签、卡片缓存和分支头提示，不设置工作台的读取commit、不切分支、不刷新样本表、不提交未保存的样本输入。空main、未配置模板、权限不足、网络失败和并发版本冲突分别处理；失败保留输入，关闭时可保存、放弃或返回编辑。有权限者可进入main项目设置配置模板。

关键词从固定main的 `.oxenweb/repository.json` 读取，不能用其他分支或过期仓库摘要替代。`aisec` 优先可见；关键词采用虚线样式，与真实模板维度选项区分。卡片及顶部最多展示3项和+N，关键词参与搜索但不伪造结构化筛选选项。原四个真实项目的结构化分类在R4清理旧标签后为空；本轮已明确初始化其研究主题。这是项目目录分类，不是从样本truth推断人工判断，生产回读结果如下。

项目标签接口使用main预期提交和最新权限校验；无变化不产生提交。有效保存只写 `.oxenweb/dataset/dataset-labels.json` 一份元数据文件，保持其他工作区与分支样本草稿不变。模板维护与赋值继续分权，模板定义不在标注面板修改。具体交互见[项目标签UI说明](project-label-ui.md)。

## 表格编辑、复制与删除

- 双击可编辑的正文单元格，按原值类型使用字符串、数字、布尔、null、数组或对象编辑；非法JSON和意外类型转换被阻止，不静默替换。ID/UID等身份及既有源truth受保护，权限和任务行范围仍在前后端校验。
- 身份、数字和布尔列采用较紧凑宽度，长文本及结构化值获得更多空间。保留字段ID、显示名称、实际类型与帮助；同页选择条目继续只更新高亮和详情。
- “复制样本”创建新的逻辑身份，并处理源ID/UID或配置的业务身份，完整数据集内检查重复。复制内容和附件引用，不复制人工标签、片段/步骤及系统任务/审核记录；原truth内容不改写，不伪造原导入来源身份。新条目继续编辑时合并为同一个append操作。
- 所有样本编辑先本地暂存，再保存私有草稿；核对后一次正式提交。取消、未保存离开、刷新恢复、草稿双CAS、撤权与提交失败保留继续生效。

本轮补齐三个具体删除回归：

1. 复制项已保存进私有草稿后再删除，撤销对应append及其标注，并从已叠加的列表页移除；不留下可继续编辑的“幽灵行”。
2. 删除正在填写非法单元格输入的条目时，同时清理该条目的编辑器；保留其他条目修改及原删除CAS，后续保存不再被已删除条目的非法输入阻塞。
3. 已删除的基线条目不进入全选和批量打标候选；其他页仍有效的选中项保留，避免给删除目标重新排入赋值。

本轮开始时没有用户原失败现场的残留草稿，不能声称复现了原始错误或原HTTP状态；以上是对已定位边界的单元、集成与合成浏览器回归。

## main 样本草稿的显式恢复

项目标签保存会推进 main。若本人正在 main 上编辑样本，旧草稿继续保留，但旧基点不能直接提交。工作台现在提供“同步项目标签版本”，需要明确确认；不会自动同步。服务核对新旧提交、可验证祖先、草稿 ID/版本、固定分支头、模板指纹、样本内容与稳定身份。只有版本差异全部为 `.oxenweb/dataset/dataset-labels.json` 时允许同步；含项目标签赋值的旧草稿及其他正文、规范或文件变化均拒绝。所有样本操作按当前权限、任务范围和原内容哈希重新预检。同步只更新本人私有草稿基点并递增草稿版本，不创建 Oxen 工作区或提交；随后仍由使用者明确提交样本。

刷新后只有过期草稿摘要时，“同步”由服务恢复完整操作，不用空数组覆盖旧草稿。未保存的内存编辑则随明确请求一并保存。另增本人“下载本机草稿”入口，即使旧基点无法应用仍可导出；要求当前身份及项目读取权限。非标签变化需要导出后人工对照，不提供自动合并或覆盖。

原生专项 `scripts/r5-main-draft-acceptance.ts` 在官方 0.67 服务的既有合成项目 main 上通过：已保存草稿因项目标签提交过期后，导出操作与原草稿完全相等；显式同步保留最新未保存输入，不产生提交或工作区，最后一次样本提交成功，120 条及原始 JSONL SHA 不变。标签提交 `5d52ca5acafeeaa0b31c11d75e207a80`，样本提交 `9b67b6bc6514b27db69945e47727ce37`；回执 `.data/r5-main-draft-acceptance/verification.json`。

合成浏览器实测两条路径均通过：main 未保存 score=41 → 保存项目标签 → 明确同步 → 提交成功；main 已保存 score=43 → 保存项目标签 → 刷新出现过期摘要 → 明确同步恢复完整编辑 → 提交成功，控制台错误为 0。见[过期草稿恢复入口](evidence/r5-project-crud/stale-draft-recovery.png)与[恢复后提交](evidence/r5-project-crud/main-draft-synchronized.png)。下载按钮的浏览器审批被拒绝，未落盘、未重试或绕过；因此仅记录接口及先前原生导出验证通过，浏览器实际下载不计为通过。
