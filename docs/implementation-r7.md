# R7 编辑恢复、列宽与文本差异

日期：2026-11-08。全部改动位于 TypeScript Web/BFF；官方 Oxen 0.67 server、基础内核及四个真实 benchmark 项目未修改。本轮复用冻结 SaaS UI04/05/06/08/09/11，没有新增 SaaS 页面观察。下述恢复、列宽和细粒度文本差异属于本地实现，设计来源见[调研记录](research/durable-editor-and-diff-2026-11-08.md)。

## 配置输入与样本编辑分别保留

R6 的字段表单遇到本人样本草稿或活动任务时，真实配置提交会被正确阻止，但此前离开只能放弃表单。R7 将尚未提交的界面输入独立保存为本机检查点：字段表单和样本工作台分别使用 `field-settings`、`workbench`，按操作者、项目、分支隔离。检查点不产生 Oxen commit 或 workspace，也不绕过样本、字段规范、权限和任务校验。

字段表单自动保留原始控件输入，包含未完成的数字/枚举选项、空字符串、布尔、null/必填标志、列宽、选中字段、搜索、新字段 ID 和提交说明。无效输入不必先通过字段 PUT 校验才能离开。“保留配置并前往数据编辑”可先处理样本草稿，回来继续配置。导航等待保留结果，失败留在本页并提供重试；正式保存配置仍需 `schema.bind`、固定分支头及完整数据预检。

导航等待期间若继续输入，会核对上下文 generation 与原始表单指纹，循环保留直到输入稳定；上下文改变或持久化失败时拒绝离开。正式字段保存也先等待稳定输入，再重新校验并同步捕获 fields、提交说明和 `expectedCommit`，避免慢请求将旧表单与新界面错配。该慢等待保护新增3项回归，已纳入最终全套。

回来先读取最新字段配置。期间若只提交了样本、字段配置未变，可恢复输入并使用最新基点；若字段定义也变了，先展示原定义、最新定义和保留表单，用户明确对照后继续。未修改的字段沿用最新配置，不让旧表单自动覆盖全部新定义。成功配置提交或明确放弃后，用检查点 ID 与 revision 双 CAS 清理；其他会话更新时不会误删新版本。

样本工作台也保留完整 JSON、行内编辑和未完成原始输入，关闭抽屉、切换页面或整页刷新后可恢复。合法私有草稿与界面检查点仍是两层：检查点可以保存非法 JSON；正式草稿和提交继续校验稳定身份、字段类型、来源真值及任务范围。多窗口冲突不会自动重试覆盖；工作台的“保留两份输入后切换”保留本页及另一窗口的原始输入，再明确切换。

本地接口为 `GET/PUT/DELETE /api/repos/:namespace/:repo/dataset/ui-state`。查询指定 `ref` 和 `kind`；新建 revision 为0，更新/删除核对已有 ID 与 revision。纯 JSON 检查点上限24 MiB；不能读取其他操作者的检查点。撤回写权限后，本人已有输入仍可在有读取权限时取回/保留，实际应用仍受权限检查。

## 表格空间和列宽

数据编辑占用可用内容宽度，详情改为覆盖抽屉。选中条目只更新高亮与详情；抽屉开关不挤压表格，也不重新查询整表。Esc 可关闭抽屉，窄屏抽屉适配可用宽度，表格横向滚动留在其容器内。

项目设置 → 样本字段，在帮助说明上方维护列宽：

| 模式 | 含义与限制 |
| --- | --- |
| 自动 | 不存宽度约束，按字段类型安排 |
| 固定像素 | 整数48–2400 px，适合 ID、序号或分数 |
| 按权重 | 大于0且不超过1000，按可分配空间的份额安排；例如标题1、正文5 |

列宽是显示元数据，不改变源值、字段校验或审核含义。仅调整列宽可在本人样本草稿/活动任务存在时先保存，不把类型、选项或其他规则变更带过保护。样本草稿显式同步时，仅接受允许的元数据变化，重新核对源内容和语义规范；不静默把其他描述文件变化当作宽度更新。

## 可定位的文本与 JSON 差异

提交详情和表格变化格复用 `TextDiff`：真实行级增删、旧/新行号、上下文折叠，以及变化行内的文本高亮。英文保留空白参与比较，中文与 emoji 可定位变化；LF、CRLF、末尾无换行和空行有明确区别。

JSON 可切换结构化显示与原始文本。格式化只改变显示；大整数、精确小数、指数写法或 `-0` 不能安全往返时保留原文，避免解析时隐藏精度或字面值变化。默认显示相邻上下文，可展开不变行。两侧输入合计超过100万 UTF-16 代码单元时明确提示限制；最多渲染2500行。差异计算有时间/编辑长度预算，超限可降为明确标示的粗粒度增删，不把无法精确计算显示成“无变化”。
